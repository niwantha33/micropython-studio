Firmware / Compatibility

Match the firmware to your exact board.

Normal MicroPython USB REPL and file transfers can work on many boards. Live source debugging is different: it requires a compatible debugger-enabled image, an available transport and hardware acceptance.

Do not flash blindly. Back up your MicroPython files, verify the board and recovery procedure, and choose a verified image that explicitly matches the hardware. Never install ESP32-S3 firmware on ESP32-C3 or a Pico W image on Pico 2 W.

Which download should I choose?

01

Install the IDE

Use the approved VS Code Marketplace extension or the stable v2.6.0 VSIX. This is a PC extension, not board firmware.

02

Choose board firmware

The official firmware download matrix identifies approved vs preview releases. Match the board exactly.

03

Test safely

Confirm ordinary USB REPL before trying the separate debugger port. Only then check a breakpoint, locals, Continue, breakpoint removal and RTA On/Off.

Why two serial ports?

On the verified frozen Pico W image, the REPL/file channel is USB CDC0 and the debugger is USB CDC1. This allows normal serial access and debugging to use separate transports. Do not connect both functions to the same COM port.

ESP32-S3 differs: its preview uses the physical USB Serial/JTAG path for REPL/upload and a separate native USB debugger interface. Follow the preview guide before plugging in or flashing. Board-specific USB capabilities matter more than the name “ESP32”.
